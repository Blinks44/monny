# Monny: product specification

**Status:** specification derived from saved Monny.sketch; native-only scope revised by user instruction on 2026-10-21. Implementation and hardware support must be independently verified; a requirement here does not mean it exists.
**Platform:** macOS 26+ on Apple silicon only (Intel Macs are out of scope, user decision 2026-10-18), native SwiftUI/AppKit, distributed outside the Mac App Store.
**Companion files:** [AGENTS](../AGENTS.md), [STATE](STATE.md), [WORKFLOW](WORKFLOW.md), [PLAN](PLAN.md), [DESIGN](DESIGN.md). Visual states, layout and exact copy live in Sketch; this file owns behavior and acceptance.

## 1. Product vision

A calm, native menu bar utility that answers “what is my Mac doing?” in one click and keeps a plugged-in MacBook's battery healthy. It should feel like a first-party macOS app, cost almost nothing to run, and never claim a reading it cannot make.

**Primary test of success:** readings match Activity Monitor/System Information within stated tolerances, the app stays light while open, and an enabled charge limit is respected across sleep, restart and quit without ever leaving the Mac unable to charge.

### Non-goals

Not a system cleaner, fan controller, network firewall, cloud dashboard or analytics collector. No account, no remote access, no tuning of system settings beyond the native macOS charge-limit preference. Ending processes is limited to the explicit Quit / Force Quit actions of the Processes list (user decision 2026-10-24); Monny never ends a process on its own.

### Capability labels

Each metric, sensor and battery mode is reported with one label: `not implemented`, `implemented` (software-tested), `verified` (checked on a named Mac model and macOS version), `unsupported` (the hardware/OS does not expose it; the UI says so). Labels are recorded per task/verification record.

## 2. Menu bar presence

- A template status item (Sketch: `05 · System · Menu bar & notifications`). States: idle, popover open, needs attention (a 7 pt badge for heat or danger; can be turned off in Settings).
- Left click opens the popover; there is no hover mode (user decision 2026-10-18). Right click opens a menu: Open Dashboard (⌥⌘M), Settings…, Turn Off Charge Limit, Check for Updates, Quit Monny. Check for Updates uses the existing Sparkle updater and is disabled while it cannot start another check (user decision 2026-10-23). Turn Off Charge Limit sets the system target to 100% (no limit); it is disabled when native support is unavailable or the limit is already off and hidden without a battery. Calibration remains deferred.
- Optional readings next to the icon: CPU load, CPU temperature and battery level (battery only on a Mac with a battery). Each is off by default and turned on separately in Settings → Menu bar (user decision 2026-10-21). They use the shared sampler's values and refresh rate.
- A global shortcut (default ⌥⌘M, changeable) opens the dashboard.
- No Dock icon, except while the dashboard window is open (user decision 2026-10-18).

## 3. Popover

Header: app icon, Monny, Mac model · chip · uptime; buttons to open the dashboard and Settings. Three tabs, plus AI when AI limits are on.

**Overview:** CPU load with P/E split and CPU temperature chip (warns when hot), memory used with pressure chip, disk free space and read/write rates, network down/up rates with a short sparkline, per-core load bars grouped by Performance/Efficiency, and a battery strip with level, source state (for example “Charging · Adapter 96 W”) and, on the right, what the whole Mac uses now in watts (“Mac uses”, from the battery gauge's system load; dash while unavailable). The full source state has its own single line beneath the level and power row, so localization does not wrap it around the power caption (layout revision 2026-10-25). Footer: Open Dashboard, shortcut, refresh interval.
**Thermal state:** when the Mac is hot, the CPU temperature chip turns warning or danger.

**Battery:** source in the header (Power adapter / On battery) with the charging state chip, large level gauge with system limit marker, a power panel, health · cycles · temperature, supported native charge-limit slider and enable switch, system charging guidance. Missing readings stay unavailable/loading. Discharge and advanced automation in the Sketch frames are deferred and not shown (production review 2026-10-21). A no-battery Mac keeps the same empty state as the dashboard Battery page. Do not invent a time-to-limit from a time-to-full estimate. Power panel (user decision 2026-10-24): on adapter, watts in use (Mac plus charging) with the adapter's rated watts and a bar of the adapter's capacity split into what the Mac uses and what goes into the battery (only while charging at 1 W or more), with a legend; on battery, the Mac's draw “from battery” and macOS's time left, without a bar. Power follows the battery gauge's freshness rule after plugging in or unplugging and shows a dash until then.

**AI** (only with Settings › Show AI limits on; user decision 2026-10-22): one card per supported tool set up on this Mac (Claude Code, Codex, Cursor, Grok CLI, JetBrains AI, GitHub Copilot, ClinePass, Codebuff, Amp, Augment, Nous Portal; planned additions below) with its plan, last reading and its limits (5-hour and weekly; Cursor's monthly included usage with dollars; Grok's weekly or monthly credits; JetBrains AI's monthly quota from the IDE's local data, with purchased top-up credits shown separately) as bars of quota **left** with a pace mark, then model-specific limits (Claude “Opus only · weekly”, Codex “Spark only · 5 hours”) and Codex credits when the account has them, at the share of time left. A window with less than 10 % left is Running low, whatever the pace (user decision 2026-10-22); the mark alone shows the pace; an empty one shows Limit reached and when it is available again. A reading older than 15 minutes is stale: its age turns orange, bars turn gray and a window that has reset since shows “—”. Signed out explains how to sign in; an API key login explains that Monny cannot show subscription limits for that sign-in; no supported tool shows No AI tools found with Hide AI Limits. Footer: Checked every 2 minutes (Anthropic rate-limits faster checks; after HTTP 429 Monny waits 5 minutes). Sources and limits: [research](research/ai-usage-limits.md). Planned additions (user decision 2026-10-24): only tools whose limits Monny can read from the tool's own sign-in on this Mac, without browser cookies, pasted API keys, a separate Monny login or a Keychain prompt. JetBrains AI is implemented from local XML/same-IDE logs; the original source time controls freshness, unavailable quota shows setup guidance, unknown refill timing shows no pace/forecast, and no network/sign-in data is used. Copilot reuses the active github.com sign-in from GitHub CLI (`gh auth token --no-refresh`): monthly premium/chat/completion quotas retain their own labels, unlimited quotas are text, consumed credits are separate, and no allowance or period start is inferred. Only premium requests enter Copilot history. ClinePass reuses the Cline CLI account session for its reported 5-hour, weekly and monthly subscription windows; missing windows stay unavailable and unknown monthly duration has no pace/forecast. Codebuff reuses its CLI session for the weekly subscription quota and a separate remaining-credit balance; credits are not converted into a monthly percentage. Only the weekly Codebuff quota enters history/alerts. Both are read-only, with no token refresh or API-key fallback. Amp reuses `amp usage` for separate Free, Agent/Other and Orb allowances plus an individual USD balance; Free reset timing and rounded renewal countdowns are not inferred. Only Agent/Other and Free enter separate history metrics. Augment reuses `auggie account status` for the reported monthly credits; CLI commands are bounded/cancellable and run only for enabled tools. Nous Portal reads Hermes-owned local access tokens and queries its account endpoint for monthly quota and separate USD balances, with no token refresh, host override or ambiguous-account fallback. Unknown billing starts have no pace/forecast. Remaining candidates are Windsurf, Kiro, Kilo and Alibaba Token Plan; each is added only after its source is recorded in research. Zed, Muse Code, Gemini and cookie- or key-based services are not supported.

On a Mac without a battery the Overview battery strip shows the thermal state and fan speed instead.

Each Overview card opens its dashboard page: CPU and cores → CPU, memory → Memory, disk → Disk, network → Network, battery strip → Battery, thermal strip → Sensors (user request 2026-10-21).

**Processes:** top apps sorted by CPU, Memory or Energy. Helper processes are grouped under the app they belong to, with summed values and a process count; processes without an app (system) stay single rows (Energy is a relative estimate; per-process network has no public source and is not shown), with icon, name, memory/threads or tabs/system note and value; a link to Activity Monitor. A search field with the sort pop-up beside it filters by app or process name across all rows Monny can read, keeping the sort and the rows that fit; with no match it says only the user's own processes are listed (other users' and system-owned processes are not readable without privileges). Right click on a row offers Quit (asks the app to quit; a process without an app gets SIGTERM) and Force Quit… (force-terminates the app and its grouped processes, or SIGKILL), which asks for confirmation first (user decision 2026-10-24). Monny and loginwindow are not offered; a failure is reported and the list refreshes.

### Search by PID or port and Needs attention (implemented in build 68, 2026-10-28)

[DES-005](tasks/DES-005-process-port-search.md): the Processes search field accepts a name, PID or local TCP port ("Name, PID or port"). A number 1–65535 matches both as a listening port and as a PID, in separate sections shown only when they have rows; `:3002`, `localhost:3002`, IPv4/IPv6 loopback and http(s) loopback URLs mean a port. Parsing makes no network request. Names keep the existing grouped search. Sorting is a compact pop-up (CPU / Memory / Energy) to the right of the field (user decision 2026-10-28), hidden for number/URL queries.

A result row shows name, PID, working folder and port; a single result opens its details at once. Details show CPU, memory, executable path, the parent process (a link that searches its PID) and all local listening ports with scope. Quit / Force Quit… act on that single PID only, never its grouped app or helpers; force asks for confirmation; ••• copies the PID or path or shows the executable in Finder. Actions revalidate PID, start time, owner and the existing protections. A sent request is not success: Monny waits up to 3 s for the process to disappear, reads the query again and then reports that it quit (and that none of the user's processes listens on the port), that it is still running (Force Quit… stays available) or that a new process took the port (possibly restarted by its launcher). It never repeats or escalates on its own. Only the current user's processes are readable, so Monny never claims a port is globally free and says so in empty states.

Needs attention appears above the list while the search is empty and has rows (at most three): single processes at or above 80 % of one core for at least one observed minute, with that duration and Quit (Force Quit… in the context menu); clicking a row searches its PID. Durations come from the shared sampler; a pass without process data ends every episode. An app's "not responding" state has no public source and is not shown. Discovery runs only for a visible number/URL query and after actions, off the main actor, without a helper or port history ([research](research/process-actions.md#pidport-lookup-and-needs-attention-2026-10-28-des-005)).

## 4. Dashboard window

Sidebar: Overview, CPU, Memory, Disk, Network, Battery, Sensors, AI usage (only with AI limits on); Settings at the bottom. Header: page title and machine summary, time range 1m / 1h / 24h / 7d, and a button that collapses back to the popover.

- **Overview:** summary cards with sparklines (CPU, Memory, Temperature, Battery), CPU load & temperature chart with hover tooltip naming the top process, 24 h battery level chart with limit line, battery facts (health, cycles, capacity, system load), top processes, sensor tiles and fan speed.
- **CPU, Memory, Disk, Network:** the detailed history and breakdowns drawn in the corresponding Sketch frames.
- **Battery:** level, health, cycles and power cards (Power shows what the Mac uses now on adapter and on battery, plus watts going into the battery while charging; on-battery values are verified against a reference before they are shown), history and native charge-limit controls. Sailing, heat protection, calibration and trip cards from Sketch are not shown until implemented (production review 2026-10-21: no disabled placeholders in the release).
- **Battery without a battery:** the range control and cards are replaced by one empty state (“This Mac has no battery”) with Open Sensors.
- **Sensors:** CPU die, GPU, SSD and battery cards with peaks, temperature chart, thermal state (Nominal/Fair/Serious/Critical), fan speed, and tiles for each available sensor. Missing sensors are omitted or marked unavailable, never invented; a Mac without a fan says so.
- **AI usage:** a tile per tool with its windows, quota left of the weekly windows of each tool's longest window over 24 h or 7 d (range control 24h / 7d; four tools tile in two rows), the next four resets in local time with an estimated run-out time when a window would run out before its reset, and the sources with their connection state.

Before history exists, current values show immediately and charts/process lists explain “Collecting data…” instead of suggesting permanent emptiness or showing invented zero lines.

History must survive the window closing and an app restart for the 24 h and 7 d ranges. Storage mechanism is an open engineering decision (research).

## 5. Battery control

Main implements the **native macOS charge-limit preference only**, without a privileged helper. Requires an internal battery, macOS 26.4+ and a compatible native runtime. On macOS below 26.4, replace the charge-limit controls with an informational message explaining the minimum version and that battery monitoring still works. The runtime returns supported targets (currently 80/85/90/95/100). Only explicit user actions set the target/enable state; startup, activation and wake read back settings without replaying a target.

Monny changes the same system preference shown in Battery Settings. macOS owns charging enforcement and the preference persists after app quit, crash, sleep and restart. No restoration-on-quit, privileged helper, XPC, SMC writer, isolation or recurring policy is required on main. On failure, re-read state and report that the setting could not be confirmed. Unsupported/unknown readings disable mutation; no root/entitlement/preferences-file workaround. The private runtime interface is not a public API guarantee and must fail unavailable when signatures change.

The control mirrors System Settings: one 80–100% slider, where 100% means no limit (Monny turns the native limit off) and a lower target turns it on. Monny never writes an enabled limit of 100%. Enable only when necessary, before setting the target (enable can reset it); require actual enabled/target read-back. A switch below the slider turns Optimized Battery Charging on or off through the same native runtime, with read-back; it is hidden when that setting cannot be read (user decision 2026-10-22). The system may charge within a few percentage points of the target and occasionally reach 100% for estimation. Do not claim exact thresholds, immediate forced discharge on lowering a target or a fabricated time-to-limit. Provide a Battery Settings link and explain that the setting persists.

Discharge, sailing, manual heat protection, calibration and trip automation are deferred to **experiments/discharge**, preserved at 09595b5. Their Sketch frames remain for later work; the app does not show them.

Users of historical helper builds remove that helper through the old app before replacement. The new app never silently installs/uninstalls a daemon or deletes old recovery storage.

## 6. Onboarding

Three steps from Sketch page `03`: Welcome, Charge limit and Ready; no helper step or administrator approval. Charge limit explains the native limit and offers Not Now or Use 80% Limit (an explicit gesture that enables it); it is skipped on a Mac without a battery or where the native limit is unavailable. Explain menu bar monitoring, offline behavior, supported native system limit and the global shortcut. Launch at login is a monitoring convenience, not required for macOS to enforce a persistent limit. Ready also offers Check for updates automatically (on by default, user decision 2026-10-21); it is the same setting as in Settings › About and replaces Sparkle's own permission prompt. A third row, Show AI limits, is off by default and is the Settings switch. Macs without a battery omit charging references. Onboarding implementation remains a separate release gate; no Sketch edits are authorized in this slice.

## 7. Settings

- **General:** Launch at login, refresh rate, temperature unit, appearance, language (System or one of the six; applies after Monny restarts, with a Restart button; user request 2026-10-18).
- **Menu bar:** global shortcut, show alert badge, show in menu bar (CPU load, Temperature, Battery level; all off by default).
- **AI limits:** Show AI limits (off by default), with the tools found on this Mac in its subtitle; with two or more found, a checkbox per tool (unchecked tools are not read).
- **Battery:** the same supported native limit/enable setting as the Battery page. Advanced automation preferences are deferred.
- **Notifications:** charge limit reached, Mac is running hot, an app keeps the Mac busy (one app, helpers included, above 80 % of one core for 5 minutes; off by default), battery below 20 %, memory pressure is high, AI limit is running low (off by default, only while AI limits are on; once per window episode, also when a window is used up) (each toggle; battery ones only on a Mac with a battery). Each alert fires once per episode; charge limit reached fires once per plug-in, because macOS lets the level drift slightly below the limit. Calibration finished comes with calibration.
- **About:** version and build, Check for Updates, Check for updates automatically (toggle), privacy note (no analytics; network only for updates, and for AI limits when they are on). Updates use Sparkle (user decision 2026-10-21): Sparkle's standard window shows release notes and Install Update / Skip This Version / Remind Me Later; Monny installs and relaunches only after the user confirms. Automatic checks run in the background (daily) only while the toggle is on; no silent installs and no system profile is sent. Updates are verified with an EdDSA signature. Up to date and check failed use Sparkle's standard alerts.

## 8. Cross-cutting requirements

- Light and Dark appearance; Increase Contrast, Reduce Motion, VoiceOver and full keyboard navigation in popover and window.
- Localized in English, Russian, German, French, Spanish and Simplified Chinese; numbers, units, temperatures and dates use the user's locale and chosen temperature unit. Keep Mac in Latin script in every language. Copy must distinguish estimates and unavailable readings from guarantees; localized labels must fit their native controls.
- Readings never leave the Mac. Update checks (manual, or automatic when enabled) and update downloads are the only network requests, except AI limits: when the user turns them on, Monny asks the services of the enabled tools (Anthropic, OpenAI, Cursor, xAI, GitHub, Cline, Codebuff, Amp, Augment, Nous Portal and the planned additions) for the plan limits with the sign-in the tools keep on this Mac; local-only sources such as JetBrains AI make no request. Gemini is not supported ([research](research/ai-usage-limits.md#gemini-not-implemented)). Monny never stores, renews or sends those tokens elsewhere.
- Idle cost: the popover and dashboard must not keep the CPU busy; target and measurement method are defined in the sampling task.

## 9. Open product decisions

- Time estimates (“about 1 h 05 min left”, “80% in 25 min”): proposal is to show macOS's own estimate and hide it while macOS is still calculating, instead of computing our own.

## 10. Public website

Product components use a folder with `Component.tsx`, `Component.module.css` and `index.ts`. Prefer direct library use and simple code over custom primitives or generators.

Implement in two iterations: (1) application, dependencies, tokens, localization, SEO and deployment configuration; (2) full transfer of `Monny.sketch → 05 · Website`. The website is dark only per that source. Content must describe current app behavior and limitations, with no fabricated readings, performance figures, ratings, release downloads or deferred charging features.
