The initial screening below used only public source/documentation, without local credential access or authenticated requests. The user subsequently authorized the implementation described next. ## Implementation decision and result — 2026-11-08

The user authorized all qualifying additions plus website listings, accepting issue-based real-account follow-up. Implemented nine sources: OpenCode Go, Kilo, API-only Kiro, Alibaba Token Plan, Alibaba Coding Plan, local Windsurf, CodeRabbit counts, eligible work-account Gemini CLI and Hugging Face ZeroGPU. The original screening remains below as dated rationale; implementation details here supersede tentative choices. New readers use native Foundation/system SQLite and the existing bounded child runner; no package/source was copied or installed.

- **OpenCode Go:** default `.local/share/opencode` only. Read active v2 `credential` table rows (Go preferred over general OpenCode; duplicate selected integration rejected), otherwise legacy `auth.json` only when the v2 table is absent. OAuth expiry checked with a safety margin. Fixed `GET /inference/go/v1/usage`; no cookie or old-account fallback. Reported session/weekly/monthly meters each have separate history; monthly duration is unknown.
- **Kilo:** default CLI `kilo.access`; JWT expiry when present. GET tRPC batch `user.getCreditBlocks,kiloPass.getState` only, not payment-method discovery. Explicit USD balance and pass base+reported bonus allowance stay separate; unknown schemas stay unavailable. No organization guessing, renewal or purchased-credit percentage bar.
- **Kiro:** require one token and explicit valid profile in CLI SQLite; fixed US East/Frankfurt hosts only. Direct GetUsageLimits, no chat or whoami subprocess. Plan usage subtracts explicitly reported overage, rejects ambiguous bonuses; optional overage has its own label and does not enter plan history. Missing profile, unsupported region or incomplete plan reading is unavailable. No monthly duration is invented.
- **Bailian:** use the user's saved default console/profile/region, with no profile switches or region probes. Official CLI at `cadc301d078f0fd1f2c56f7bf94f32c55bbb055d` supplies direct JSON from `bl usage token-plan --output json` (per* ratio/reset fields, hasQuotaData) and `bl usage coding-plan --output json` (per5Hour/perWeek/perBillMonth counters/ratios). This replaces the screening's provisional custom console calls: the supported CLI now supplies monthly data directly. These commands require console auth; model-only keys and Team seat aggregation are outside this reader. The CLI owns saved sign-in; Monny never invokes login/refresh. Bounded execution, null stdin and narrow environment apply. CLI-internal expiry behavior is a real-account check.
- **Windsurf:** read one cachedPlanInfo entry with reported quotaUsage or message/action counters. Never use database mtime as reading time: `sourceDateUnknown` keeps readings visibly cached/stale and excludes them from alerts/history. No browser or web API fallback.
- **CodeRabbit:** deliberately use the established `coderabbit usage` text report, not an invented NDJSON schema. Display only `Your reviews`; no quota denominator, balance or reset is inferred. Disable CLI auto-update in the child environment. Current structured allowance support can be added after a real response/schema is available.
- **Gemini:** valid saved CLI access token only. Call loadCodeAssist to obtain its project, then retrieveUserQuota; no project-list enumeration, client-secret extraction or renewal. Consumer migration sentinel shows setup guidance; supported work tiers retain Pro/Flash/Flash Lite labels with no invented period. Pro enters history; the other model groups remain separate display/alert rows.
- **Hugging Face:** default `.cache/huggingface/token` saved by its CLI only. Fixed official GET `/api/spaces/zero-gpu/quota`, `base`/`current` GPU seconds and optional `resetsAt`. Billing permission is required; no inference spend/credit estimation or browser-wallet fallback. Official huggingface_hub `HfApi.get_zero_gpu_quota` and reference plugin informed the wire shape.

Shared SQLite reads are read-only and bounded; immutable mode is used without WAL. A WAL without an existing shared-memory file is unavailable, preventing sidecar creation. Changed/unsupported stores do not trigger credential migration. All new tools reuse opt-out, cadence, stale/429 handling and fixed-host/no-redirect transport. New fields are optional for saved-reading compatibility. Neutral letter tiles reuse Sketch frame 23; source was inspected live without edits/save. Website adds all nine plus the previously missing Kimi label, with a six-language limitations note. No deployment/publication is part of this change.

Software/package evidence and remaining real-account checks: [APP-015](../tasks/APP-015-ai-usage-limits.md#browser-free-provider-expansion--2026-11-08).

## Scope and evidence

Preserve the existing contract: reuse an installed tool's saved sign-in; no Monny login, pasted keys, browser storage import, interactive Keychain access or Monny token renewal. Reading a key already saved by a tool is technically possible but is not automatically an approved expansion to arbitrary provider-key discovery. A CLI's own normal sign-in may open a browser; that differs from Monny extracting browser credentials.

Sources: current official vendor documentation plus MIT [CodexBar](https://github.com/steipete/CodexBar) at **7447bc77c2497323d9c41e40164ce705533493c8**. Its [provider inventory](https://github.com/steipete/CodexBar/blob/7447bc77c2497323d9c41e40164ce705533493c8/docs/providers.md) was screened for local sign-in, usage-only commands and local caches. Detailed docs and selected fetchers were read from that revision. CodexBar is an implementation reference, not provider endorsement or proof of live account compatibility. No code copied, dependency installed or new library proposed; Foundation, system SQLite and Monny's bounded command runner should cover the shortlisted source types. Snapshotting public source avoids relying on changing `main` links.

## Recommended candidates

| Candidate | Browser-free source | What it can report | Main limit / next check |
| --- | --- | --- | --- |
| **OpenCode Go** | Existing OpenCode CLI credential, legacy JSON or v2 SQLite; bearer usage request | Reported 5-hour, weekly and monthly meters and reset times | Credential-schema/account selection and current canonical API path; do not estimate quotas from local session costs |
| **Kilo / Kilo Pass** | `~/.local/share/kilo/auth.json`, `kilo.access`; bearer tRPC | Pass allowance/reset when returned, separate credit balances | Pass credits differ from purchased credit blocks; verify current plan shapes and token expiry |
| **Kiro** | Read-only CLI SQLite token/profile; regional `GetUsageLimits` | Monthly plan credits/reset and separate overage | Private regional contract; bonus-inclusive totals can prevent reliable plan-only quota |
| **Alibaba Token Plan** | Signed-in Bailian `bl` usage/console commands, JSON output | Team allowance or Personal/Solo 5-hour, weekly/monthly windows | Explicit region/plan selection; console sign-in, command side effects and expiry must be checked |
| **Windsurf (local only)** | Read-only app SQLite cached plan information | Cached daily/weekly percentages or message/action allowances | Cache may be old and may lack a trustworthy original reading timestamp |
| **CodeRabbit** | Existing CLI sign-in; `coderabbit usage --agent` | Official docs now describe usage, shared review cap and permitted credit balances | New structured contract needs real sample/schema verification; shared cap is not necessarily a personal quota |

### OpenCode Go: first choice for a source prototype

[Official Go docs](https://opencode.ai/docs/console/go/) describe rolling, weekly and monthly allowances and ordinary tool setup. CodexBar's [Go source notes](https://github.com/steipete/CodexBar/blob/7447bc77c2497323d9c41e40164ce705533493c8/docs/opencodego.md) establish read-only CLI credential reuse: older `~/.local/share/opencode/auth.json` has an `opencode-go` API entry; newer installs store active integration credentials in SQLite, including general `opencode` OAuth. Existing v2 credential storage must prevent revival of logged-out legacy credentials. A specific Go credential takes precedence over a general login; ambiguous/unsupported selections must fail closed.

Its [fetcher](https://github.com/steipete/CodexBar/blob/7447bc77c2497323d9c41e40164ce705533493c8/Sources/CodexBarCore/Providers/OpenCodeGo/OpenCodeGoUsageFetcher.swift) uses `GET https://opencode.ai/zen/go/v1/usage`: `usage.rolling`, `weekly`, `monthly`, with percent/reset fields. A [discussion in the vendor repository](https://github.com/anomalyco/opencode/issues/52227) identifies `/inference/go/v1/usage` as the canonical replacement, with the old route still supported. That path claim is a repository discussion, not a versioned public API guarantee: verify before implementation, use a fixed trusted host, never arbitrary credential-bearing redirects. Do not copy CodexBar's fallback fixed-dollar quota estimates or scan history for this slice. Public docs now describe model-dependent allowances; do not infer per-model quotas from aggregate API meters.

### Kilo: ordinary local token path, more quota semantics

[Official CLI reference](https://kilo.ai/docs/code-with-ai/platforms/cli-reference) documents provider login. CodexBar's [credential resolver](https://github.com/steipete/CodexBar/blob/7447bc77c2497323d9c41e40164ce705533493c8/Sources/CodexBarCore/Providers/Kilo/KiloBearerTokenResolver.swift) reads `kilo.access` from the default CLI file. Its [usage fetcher](https://github.com/steipete/CodexBar/blob/7447bc77c2497323d9c41e40164ce705533493c8/Sources/CodexBarCore/Providers/Kilo/KiloUsageFetcher.swift) issues a GET tRPC batch to `https://app.kilo.ai/api/trpc` with `user.getCreditBlocks`, `kiloPass.getState` and an optional payment-method procedure. Monny should request only the quota/balance procedures it needs; do not collect payment metadata. Keep pass allowance/bonus, purchased balance and organization spending separate. Start with one unambiguous personal account; organizations need their own explicit selection contract. This is a candidate for subscription/credit monitoring, not a promise of 5-hour/weekly windows.

### Kiro: direct API is now a stronger candidate

This supersedes the October screening's assumption that the reference must start a chat first. Current [notes](https://github.com/steipete/CodexBar/blob/7447bc77c2497323d9c41e40164ce705533493c8/docs/kiro.md) and [API reader](https://github.com/steipete/CodexBar/blob/7447bc77c2497323d9c41e40164ce705533493c8/Sources/CodexBarCore/Providers/Kiro/KiroUsageLimitsAPI.swift) support API-first quota reads. The CLI database is `~/Library/Application Support/kiro-cli/data.sqlite3`: `auth_kv` / `kirocli:odic:token` contains `access_token`; `state` / `api.codewhisperer.profile` contains the profile ARN. POST to the fixed supported regional AWS host with `X-Amz-Target: AmazonCodeWhispererService.GetUsageLimits` and profile ARN; region is selected from that ARN, not guessed from the authentication region.

A scoped Monny integration should use API only and wait for the CLI to renew expired credentials. Do not run `chat /usage` or `/context`: the reference records saved empty sessions and V3 slash commands potentially sent as model prompts. Missing/ambiguous bonus separation means unavailable plan quota, not invented headroom. The API does not establish the CLI plan name or context breakdown.

### Alibaba: reusable command runner, extra account setup questions

[Official usage docs](https://docs.agent.bailian.aliyun.com/en/bailian-cli/capabilities/usage-quota) document `bl usage token-plan --output json` and also **`bl usage coding-plan --output json`**, making Coding Plan an additional investigation candidate beyond the earlier list. [Official authentication docs](https://docs.agent.bailian.aliyun.com/en/bailian-cli/getting-started/installation) distinguish saved console login from model-only Token Plan keys. Existing `bl` console sign-in is the qualifying source; Monny must not launch login or ask for a cloud key.

The [reference implementation](https://github.com/steipete/CodexBar/blob/7447bc77c2497323d9c41e40164ce705533493c8/Sources/CodexBarCore/Providers/Alibaba/AlibabaTokenPlanCLIUsageFetcher.swift) uses explicit region/site flags for Team and a bounded `bl console call --api zeldaHttp.apikeyMgr./tokenplan/personal/api/v2/usage --data '{}'` for Personal/Solo, avoiding older monthly omissions. Check subscription/quota metadata requirements before claiming all windows. Inspect CLI expiry behavior and disable interactive login/updates; whether a usage command itself renews saved console state remains unverified. No account, region or browser fallback. Coding Plan has an official command but its response/schema/account coverage was not established here, so it is not implementation-ready.

### Windsurf and CodeRabbit: useful but qualified

[Windsurf local source](https://github.com/steipete/CodexBar/blob/7447bc77c2497323d9c41e40164ce705533493c8/docs/windsurf.md): `ItemTable` key `windsurf.settings.cachedPlanInfo` in `~/Library/Application Support/Windsurf/User/globalStorage/state.vscdb`; `quotaUsage` or newer `usage` counters. This avoids network/auth access entirely, like JetBrains. It only updates while Windsurf runs. A database mtime can reflect unrelated writes: establish cache-specific freshness or label the source age unknown; never make an old reading fresh on each poll. Browser-backed GetPlanStatus is excluded.

[CodeRabbit's current official reference](https://docs.coderabbit.ai/cli/reference#usage-command) documents CLI 0.9.2 `usage --agent`, emitting NDJSON usage, shared review cap and credit balances when permitted. This is stronger than CodexBar's older text parser, which explicitly lacks a quota denominator. Prototype the structured command, bound output/time and confirm the event schema before deciding bars/history/alerts. Hide counters not authorized/reported, distinguish personal consumption from shared allowances, and suppress auto-update or sign-in side effects. No code review/model work should run during polling.

## Conditional or deferred

- **Gemini CLI, supported work accounts only:** [Google's deprecation notice](https://developers.google.com/gemini-code-assist/docs/deprecations/code-assist-individuals) confirms the June 18 consumer OAuth shutdown and continued Standard/Enterprise support. The [reference](https://github.com/steipete/CodexBar/blob/7447bc77c2497323d9c41e40164ce705533493c8/docs/gemini.md) reads `~/.gemini/oauth_creds.json`, calls `retrieveUserQuota` and optionally `loadCodeAssist`. An unexpired access-token-only reader could avoid refresh/client-secret extraction; that is an inference, not a verified integration. Pro/Flash quotas need their own labels. Do not advertise personal Gemini app limits or reverse the existing unsupported product status without a scoped decision.
- **Hugging Face:** [reference](https://github.com/steipete/CodexBar/blob/7447bc77c2497323d9c41e40164ce705533493c8/docs/huggingface.md) reuses `hf auth login`'s saved token. Inference billing is spend, not a remaining allowance; ZeroGPU can expose a real quota. Billing permission and saved-key policy require review; prepaid wallet browser fallback is excluded. Lower priority for Monny's subscription-quota cards.
- **Muse Code:** [reference](https://github.com/steipete/CodexBar/blob/7447bc77c2497323d9c41e40164ce705533493c8/docs/muse.md) permits inline `providers.meta.access_token` in CLI metadata, but ordinary storage can require another app's Keychain grant. Quota can be omitted, and its `/muse-code/key` call mints an inference key rather than being a pure usage GET. Do not classify as a straightforward read-only candidate without resolving both concerns; no browser-team fallback.
- **Zed, Factory, Antigravity:** reviewed source families do not establish an equally simple qualifying path: Keychain prompts, separate/browser credentials or local-server discovery remain additional mechanisms. Factory's saved API key is not proof of reusable ordinary CLI OAuth. Exclusion is from this shortlist, not a claim of technical impossibility.
- API-key-only services (z.ai, MiniMax, OpenRouter, DeepSeek and others) remain outside this session's existing-sign-in shortlist unless a specific tool-owned source and appropriate quota endpoint are established. A public API alone does not establish either. Local model runners and token logs do not reveal a subscription's remaining quota.
