## Outcome and scope

Prepare one explicit CHIE isolation/read-back/restoration transaction, with injected acceptance and separately compiled, unbound helper hardware operations. Preserve the user's native limit, reject competing native ownership and unknown adapter states, checkpoint before mutation, and retain retryable recovery after partial failures. Use separate fixed recovery files without changing the live native journal's default path/format.

A fixed helper-only setter and uncached native/source reader are prepared but not constructed by the daemon. The revisioned selector/CLI is now prepared separately in BAT-024, advertised false by the shipped helper. There is no production adapter backend, helper installation or physical adapter test in this slice. Existing crash/helper-restart gates remain open. The value transaction itself has no timer; the existing helper executor now drives a three-second watchdog and lifecycle recovery only when a test explicitly supplies an adapter backend. The shipped construction supplies none.

## Implementation and evidence

`AdapterVerificationTransaction` is a synchronous Sendable value owned by the off-main serialized helper executor when explicitly injected. It accepts explicit operations; app-target `SMCConnection` remains read-only and no production helper/IPC/CLI path constructs the adapter transaction. It requires the reviewed CHIE hex_/one-byte/0xD4 signature, initially allowed input (0), fresh monotonic observations no older than two seconds, physically connected adapter, a valid native snapshot and no active Monny native owner. Engineering probes refuse battery level below 30%; this is a test precondition, not a product charge limit. Attributes/readability are never interpreted as write permission.

A schema-1 CHIE 0→8 recovery intent is saved before the semantic setter. The three-second budget covers checkpoint/setter time and cannot be renewed by another begin. Successful byte read-back only arms observation. Battery-source/no-charge evidence with unchanged native settings is needed before restore/read-back/clear can return an isolation-observed result. The restored byte alone is not physical wall-power restoration proof. Unknown states, stale/missing readings, external native changes, cancellation and elapsed budget stop the probe and recover or retain restorationRequired. Recovery does not depend on telemetry or honour cancellation; it never writes a native limit.

Extracted `ChargeRecoveryJournal`/`ChargeRecoveryFileJournal` from existing native storage, keeping the old names as compatibility aliases and the native record's path/schema/default unchanged. Two fixed record names isolate native and adapter checkpoints; no filename/path input from IPC. Existing owner/mode, no-follow, bounded-data, atomic rename/fsync and file-link protections stay in the shared implementation. The adapter namespace is never opened by the live daemon in this slice.

`ChargeCommandExecutor` accepts an optional injected adapter backend and shares its existing authenticated tokens, one-owner admission and expiry task. The watchdog is armed before begin; a new begin cannot renew it. Adapter recovery runs before native startup recovery and admission, including when the native factory fails. Sleep/disconnect/removal/shutdown/expiry restore through the same path. Adapter verification and native commands cannot overlap, foreign observation/disconnect cannot take ownership, and status refuses to label an active probe notControlling. The default nil backend exposes no new wire capability or selector. Failed recovery retains its checkpoint and blocks commands; removal can retry explicitly.

## Review and limits

- The value core has no timer; injected executor/watchdog/startup/lifecycle integration is software-tested. Production construction, an independent physical-presence provider, writable IPC/CLI and physical post-restoration acceptance are absent. The helper-only setter is compiled but unbound. The adapter result is never advertised by the shipped helper.
- No synchronous private/IOKit call has a hard completion deadline. A same-process timer cannot recover a crashed or blocked helper; real restart/recovery acceptance remains open.
- A CHIE byte is not a hardware compare-and-swap. Another tool writing the same value cannot be identified from read-back alone; single ownership within Monny cannot establish cross-process exclusivity. Manual verification requires other charging controllers to relinquish control.
- The probe refuses an active Monny native session and leaves the OS setting alone. Coordinated native-limit-plus-adapter Discharge is still a separate unverified behavior, not delivered by these coexistence fixtures.

## Unbound hardware operations — 2026-10-20

`MONNY_BATTERY_HELPER` is inherited only by helper Debug/Release configurations. Under that condition, `SMCConnection.setAdapterIsolated` exposes a Bool-only CHIE operation: discard cached metadata, inspect the exact signature/known byte, build a fixed one-byte command-6 request, and retain kernel/SMC error checking. No arbitrary key/byte API. A newly observed 8 refuses isolation; restoration of an already observed 0 is idempotent. Shared `AdapterIsolationCommand` validates both transaction reads and setter admission. Metadata is a safety precondition, never write permission. The transaction still owns checkpointing, read-back and recovery; a setter acknowledgement alone is insufficient.

`AdapterVerificationOperations.make` exists only in the helper source group and has no call site. Each synchronous SMC closure owns a local connection without shared mutable handles or unchecked Sendable. Environment acquisition reads native getters and one internal-battery IOPowerSources description anew, with no application sampler/cache dependency. `AdapterPowerObservation` rejects missing/unknown source, missing/non-Boolean charging/presence, invalid capacities and contradictory battery+charging reports. ContinuousClock measures the entire acquisition interval, including a sleep crossing; this bounds acquisition age, not underlying firmware publication latency. Physical cable evidence and current native ownership require explicit providers; there are no default values. A nil cable observation fails closed. Public source selection and adapter-description presence are not silently substituted for cable evidence. The physical provider remains unimplemented/unverified.
